# Проверка системы

Команды выполняются из корня проекта; нужен JDK 21.

## Демонстрационные данные

После [запуска системы](../README.md#запуск):

```sh
./gradlew :verification:run --args="http://localhost:8080"
./gradlew :verification:run --args="http://localhost:8080 --verify-only"
```

Первая команда создаёт будущие брони и отмену через API, затем проверяет результат. Вторая проверяет уже подготовленные данные. Проверяются история, доступность номеров, счётчики и отчёт загрузки. При другом порте Gateway замените адрес.

Повтор в тот же UTC-день не создаёт дубликатов. После смены даты или ручного изменения демонстрационных объектов выполните общий сброс по корневому README. Состав набора — в [demo-fixtures](../demo-fixtures/README.md).

## Сквозные тесты

```sh
./gradlew systemTest
```

Нужны Docker Engine и Compose. Используются стандартные настройки Docker CLI. Тест создаёт отдельный проект на свободных портах, собирает приложения, проверяет доступность через Gateway/Eureka и выполняет сценарии:

- регистрация, права, каталог, бронирование, отмена, история и отчёт;
- 8 конкурентных запросов на 3 номера и 6 повторов одного ключа;
- потеря ответа после подтверждения в Hotel, фоновая компенсация и освобождение номера.

Контейнеры и сеть теста удаляются при успехе и ошибке. Логи сохраняются в `verification/build/system-test/<project>/`. Ненулевой код завершения означает неуспешную проверку. Состав результатов сопоставлен с ТЗ в [карте приёмки](../docs/acceptance.md).
