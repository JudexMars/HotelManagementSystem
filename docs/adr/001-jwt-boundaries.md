# ADR 001: независимая проверка JWT

## Решение и причина

Gateway и каждый backend самостоятельно проверяют пользовательский JWT. Проверки только на Gateway недостаточно: сервис должен сохранять разграничение доступа и при прямом обращении.

Booking выдаёт токены и публикует ключи проверки. Для обращения к календарю Hotel используются отдельные сервисные токены с собственным назначением и полномочиями. Роль ADMIN не даёт межсервисных прав. Это отделяет административные операции пользователя от протокола согласования брони.

## Последствия

Проверяющие сервисы зависят от доступности публичных ключей Booking при загрузке неизвестного ключа. Ключ подписи хранится в памяти, поэтому после общего перезапуска требуется новый вход. Немедленный отзыв пользовательских токенов не реализован: изменение роли или удаление пользователя не прекращает действие уже выданного токена.
